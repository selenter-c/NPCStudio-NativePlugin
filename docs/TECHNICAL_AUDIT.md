# NPCStudio: технический аудит перед переработкой

Дата: 2 ноября 2026. Цель этапа — изучить существующий проект, механизмы референсных модов и ограничения. Это проект архитектуры, а не отчёт о готовом моде. Игровая проверка не выполнялась.

## 1. Зафиксированные требования

- Целевая игра: Skyrim SE/AE 1.6.1170. Поддержку VR и 1.5.97 пользователь не запрашивал.
- Один интерфейс Magelight UI: список NPC, создание, редактирование, внешность, волосы/цвет, раса, имя, голос, экипировка, пресеты, биография.
- Собственные постоянные слоты: 80 женских и 80 мужских. Существующие персонажи Build a Follower не считаются автоматически перенесёнными.
- Превью персонажа целиком и головы, вращение, масштаб; изменения экипировки и внешности видны в превью.
- Сохранение пользовательских пресетов и готовые комплекты стражников разных владений, бандитов, горожан и других ролей.
- Генерация биографии заранее по шаблону с передачей данных NPC в LLM через SkyrimNet.
- Сборка через NPCStudio-Build/build.bat. Не запускать clean без необходимости.
- Текущий запрос ограничен исследованием. Реализацию согласуем на следующем этапе.

Изучены 4 приложенных скриншота и все 5 изображений Reference. Их надписи не являются дополнительными требованиями: число 32 в одном макете не заменяет 80+80; Elara не является обязательным названием проекта; блеск волос, возрастные генераторы и все переключатели макета не считаются существующими API движка.

## 2. Что существует в NPCStudio

| Подсистема | Фактическое состояние | Следствие |
|---|---|---|
| UIManager + PrismUIBridge | Открытие панели, список баз NPC, команды viewer, настройка паузы | Переписать транспорт и lifecycle под Magelight |
| NPCFactory | Перечисляет TESNPC всех плагинов и CreateReferenceAtLocation выбранной базы | Это каталог ActorBase, не список собственных постоянных NPC |
| AppearanceManager | CloneAppearance возвращает false | Реального редактора нет |
| InventoryManager | AddItem/EquipItem возвращают false | Экипировка не реализована |
| PresetManager | Save=false, Load={}, List=[] | Пресеты не реализованы |
| SkyrimNetBridge/BioGenerator | Initialize/Generate возвращают false | Интеграции нет |
| NameDistributor | Назначение=false, генерация пустая | Переименование не реализовано |
| include/PublicAPI.h | Только TODO | Нельзя считать SDK подключённым |
| NIF viewer | Собственный D3D11 device, nifly, shader без текстур, PNG/base64 в HTML | Это отдельный просмотрщик геометрии, не полноценное игровое превью |
| NPCModelAssembler | Тело по захардкоженному male/female пути, GetArmorPaths пустой | Не отражает реальную экипировку, race skin и всю внешность |
| Papyrus | Исходники есть, в полученном архиве PEX нет | Скрипты не исполнятся просто от наличия PSC |
| ESP | 148 байт, только TES4, заголовок 20 байт вместо 24 для Skyrim SE | Генератор необходимо заменить; QUST и пул отсутствуют |

В plugin.cpp нет регистрации сериализации пула; new-game/post-load события только логируются. В UI callbacks есть прямые обращения к RE:: — при переходе на Magelight это недопустимо без диспетчеризации на игровой поток.

Факт контрольной сборки: build.bat завершился с кодом 0 за 26 секунд. Создан NPCStudio-Build/dist/NPCStudio-0.1.0-fomod.zip, 14 файлов, около 674 KB. Лог: baseline-build.log. Сборка и ZIP-проверка не обнаружили дефект ESP и отсутствие PEX. Этот архив не является готовой проверенной версией мода и не установлен.

## 3. Build a Follower 2.6.6

Прочитаны README, обработчик загрузки игрока, основные цепочки применения внешности, сохранения/загрузки и проверки вариантов пула.

HouseCarl подтвердил в активном BuildAFollower.esp: 160 NPC_, 160 ACHR, 160 ColorRecord, 1 CELL, 1 QUST, а также вспомогательные классы, packages и списки. Это отдельная база и отдельная размещённая ссылка на каждый слот, а не 160 копий общего vanilla NPC.

Полезные механизмы:

- Подготовленные NPC находятся в служебной ячейке; занятый слот призывается перемещением существующей ссылки.
- Внешность применяет CharGen.LoadExternalCharacterEx с mode=15; нужен комплект jslot + nif + dds с одинаковым basename.
- До применения проверяются файлы и загруженный 3D; после смены расы восстанавливаются экипировка и голос.
- FaceGen копируется в каталоги конкретного ESP. Папки должны существовать, успешность копирования проверяется.
- Нельзя удалять FaceGen используемого актёра с загруженным 3D: при пересборке головы возможны marker/error mesh и CTD.
- Переключение Standard/Female Only/Male Only в существующем сохранении опасно: варианты переиспользуют FormID с другим полом.

Ограничения именно внешнего экспортного пути BAF: запечённые волосы теряют физику, есть ограничение отсечения головы, overlays не равны tintInfo. README самой поставки отмечает отсутствие полного игрового тестирования. Не выдавать этот путь за универсальное решение NPA.

Рекомендация: собственный неизменный пул NPCStudio.esp с 80+80 базами, размещёнными persistent-ссылками и отдельными цветами волос. Не править BuildAFollower.esp и не использовать его слоты скрытно. Persistent не означает Essential: смерть, бессмертие, respawn и сохранность ссылки — разные свойства.

## 4. NPC Preset Applier 3.1.0

Прочитаны README, INI и лицензия. Возможности: jslot-пресеты, портреты, проверка head parts/зависимостей, голова отдельно, причёска/цвет с Keep/Cancel, создание пресета из NPC, восстановление исходного вида, повторное применение и очистка остатков co-save.

NPA поддерживает уникальных и фактически единственных именованных NPC. Массовые guards/bandits с общей базой исключаются. Для создаваемых NPC это ещё один аргумент в пользу собственной уникальной базы на слот.

Исходники не опубликованы в предоставленной поставке; README говорит о возможном выпуске исходников при прекращении поддержки. Документированного внешнего API применения пресета/волос в поставке не найдено. Нельзя обещать прямое встраивание NPA, копирование его редактора или полного поведения один к одному. Лицензия допускает личное изменение и отдельные add-ons, но не перенос/распространение его частей без разрешения.

Рабочая основа: собственный сервис внешности на RaceMenu, собственный интерфейс Magelight. NPA остаётся функциональным референсом. Конфликт двух редакторов одного NPC нужно диагностировать; назначение одного владельца внешности обязательно.

## 5. RaceMenu

RaceMenu.bsa распакован через HouseCarl в research/RaceMenuBsa (629 файлов), оригинал не изменялся. Прочитаны scripts/source/chargen.psc и ModderResource/IPluginInterface.h. Точечно скачаны официальные исходники PresetInterface.h/.cpp и PapyrusCharGen.cpp в research/RaceMenuSource; master не доказывает ABI установленной DLL.

- CharGen.LoadCharacterPreset/Ex помечен предупреждением DO NOT USE ON NPCs; не использовать его как универсальную загрузку NPC.
- SaveCharacterPreset в Papyrus документирован как работающий сейчас только с игроком. Поэтому кнопка «сохранить любой NPC» требует отдельной реализации, а не простой подмены Actor параметра.
- C++ IPresetInterface декларирует SavePreset/LoadPreset и предупреждает об изменении TESNPC: актёр должен быть уникальным. Проверять версию интерфейса через exchange message, не угадывать vtable.
- В скачанном upstream master реализация SavePreset заканчивается return false даже после попытки экспорта. Само наличие метода не доказывает корректный статус или экспорт произвольного NPC. Нативный C++ интерфейс — кандидат для собственной реализации; загрузка jslot сама по себе ещё не гарантирует правильный FaceTint/sculpt/overlays/повторную загрузку головы.
- bExternalHeads в локальном skee64.ini = 0. NPA рекомендует 0, экспортный путь BAF требует 1. Нельзя автоматически менять общий ini и объявлять конфликт решённым.

Рекомендуется сначала отдельный прототип: уникальный слот, vanilla preset, смена волос/цвета, unload/reload 3D, save/restart/load, затем High Poly Head/custom race/SMP/тело. Выбор основной цепочки внешности принимать по результатам этого прототипа.

## 6. SeverActions и живое превью

Изучены поставка, скриншот гардероба, native API и Bio Blocks API, опубликованный README. В локальной поставке указан SeverActions 4.7.0, Magelight 1.7.1. Официальный README описывает живое 3D-превью и Live Stage с самим актёром.

Публичный репозиторий содержит поставку; README прямо сообщает, что исходники native и сборочные инструменты находятся в приватном репозитории. Попытка полного клонирования остановлена после проверки этого факта; уже имеющаяся локальная поставка достаточна для анализа открытого контракта. Скачанный README сохранён в research/SeverActions-README.md. Не утверждать, что native renderer SeverActions изучен по исходникам.

Опубликованный NATIVE_API.md не предлагает сервис рендера актёра для стороннего UI. Magelight умеет показать готовую текстуру, но не создаёт за нас Skyrim actor renderer.

Варианты собственного превью, которые ещё нужно проверить:

1. Игровая сцена/клонированный 3D актёра в offscreen target с использованием движка. Кандидат для точной внешности, материалов и экипировки; требует восстановления render/camera/light state и проверки 1.6.1170.
2. Отдельный stage-актёр/служебная сцена. Требует изоляции AI, коллизий, событий, SkyrimNet и восстановления состояния. Не перемещать реального NPC ради обычного предпросмотра без доказанной необходимости.
3. Собственный nifly renderer: запасной путь для предметов/диагностики; полноценный NPC потребует материалов, skinning, morphs, FaceTint и анимаций. Не расширять этот путь по умолчанию.

Первая техническая проверка должна доказать сам рендер актёра; создание текстуры через Magelight отдельно этого не доказывает.

## 7. Magelight UI 1.7.1

Официальный репозиторий скачан в research/MagelightUI, tag v1.7.1, commit 05d05d8cf13164e0dead3596640f28c058b9b307. Прочитаны API, C++ руководство, SDK, manifest и инструкция миграции PrismaUI.

Предлагаемая интеграция: собственная регистрация NPCStudio, API v4, страницы Data/Magelight/NPCStudio/...; C ABI и wrapper из официальных headers. Абсолютный UTF-8 путь строить от exe, не текущей директории. Проверять minHost и функции, добавленные позже.

- JS callbacks приходят с render/page thread; копировать аргумент и передавать игровую работу через PostGameTask. Не трогать RE:: из JS listener.
- Текстура должна принадлежать игровому D3D11 device. Текущий отдельный device viewer нельзя просто зарегистрировать вместо неё.
- RegisterTextureImage/ImageUrl/InvalidateImage позволяют выводить готовую GPU-текстуру без PNG/base64. Формат: premultiplied alpha, согласованный sRGB/UNORM; GPU capability проверяется.
- Один владелец UI mode. Нужны обработчики busy/refused, закрытия, потери фокуса, перезагрузки страницы и выхода в главное меню; восстановление паузы и управления на всех путях.
- localStorage подходит только для настроек интерфейса, поскольку общий для сохранений. Состояние NPC в нём хранить нельзя.
- Для запросов SkyrimNet через native bridge сетевой доступ HTML не требуется. Не включать Any network без задачи.

Активный MO2 сейчас разрешает Magelight.dll 1.5.1, перекрывающий копию SeverActions. Это отличается от локальных 1.7.1. Обновление/включение модов во время аудита не выполнялось.

## 8. SkyrimNet, IntelEngine и Playwright

Прочитаны DevKit beta26-rc4, PublicAPI.h, основные форматы content roots/prompts, IntelEngine SkyrimNetAPI.h и чтение биографий MemoryDB.cpp, описание архитектуры Playwright.

В старом DevKit PublicAPI v12:

- PublicSendCustomPromptToLLM доступен с v8: шаблон + variant + JSON context, асинхронный ответ.
- Callback работает на ThreadPool; строка ответа действительна только во время вызова. Скопировать ответ, проверить актуальность мира/слота, затем отправить результат в UI.
- Генерация текста, его сохранение и включение в контекст SkyrimNet — три разные операции.
- PublicRegisterDecorator с собственным character_bio subcomponent — документированный кандидат для добавления собственной сохранённой биографии в контекст без записи в чужую БД.
- PublicGetBioTemplateName — чтение имени шаблона; это не setter биографии.
- UpdateActorDynamicBio в Papyrus запрашивает обновление, но не является setter произвольного текста.

Проблема комплекта beta26: PublicAPI.h включает PublicAPIDiaryQuery.h, которого рядом нет. Не копировать только один этот header и не угадывать недостающую схему. Проверяется свежий официальный DevKit.

HouseCarl видит установленный SkyrimNet.dll 0.28.0. Опубликованные release notes более нового SkyrimNet описывают PublicAPI v14 для запроса обновления профиля с инструкциями. Свежий API должен быть опциональным и проверяться по реальному PublicGetVersion/наличию exports: номер версии DLL из manifest не равен версии PublicAPI.


Проверка свежего DevKit завершена: официальный skyrimnet-devkit-beta29.1-rc2.zip (33 406 481 байт) сохранён в research/, документация и headers извлечены в research/SkyrimNetDevKit-beta29.1. Исходный DevKit не заменён. PublicAPIDiaryQuery.h в свежем комплекте есть.

Подтверждён точный контракт:

`bool PublicRequestProfileUpdate(uint32_t formId, const char* additionalInstructions, const char* updatableBlocksCSV)`

API v14 принимает существующего Actor, при отсутствии bio создаёт первоначальный профиль, записывает динамическую биографию в слой текущего прохождения. Допускает инструкции и ограничение блоков summary/background/personality/appearance/occupation и других. Один запрос на Actor одновременно; false означает отказ постановки, true — только очередь, не готовый результат. Callback завершения у этой функции нет. Это поддерживаемый путь генерации канонической биографии после получения actor reference, но не точный setter уже отредактированного текста и не генерация без Actor. Для draft до спавна остаётся CustomPrompt + собственное хранение; затем явный экспорт/согласованное обновление.

**ABI отличается от старого комплекта.** Новый header указывает MSVC v143 (VS2022) и SkyrimNet со статической CRT /MT; старый header рекомендовал /MD. Существующая сборка NPCStudio использует VS18 Insiders MSVC 14.50 и custom triplet с dynamic CRT. До вызовов с std::string/std::function через границу DLL необходимо проверить целевую установленную сборку SkyrimNet и согласовать toolset/CRT. Нельзя механически сменить CRT только у одной библиотеки. Заголовки 0.29 и старее содержат не-inline глобальные function pointers: включать в одном translation unit; свежие используют inline и namespace SkyrimNet::PublicAPI. Magelight C ABI этой STL-проблемы не создаёт.

IntelEngine полезен как пример runtime resolution, decorators/events и работы с UTF-8. Его файловый поиск биографий по legacy prompts и сортировка каталогов сохранений не должны становиться механизмом выбора текущего мира NPCStudio.

Playwright полезен как пример действий, вывода списка актёров и native HTTP bridge. Он зависит от PrismaUI и не нужен как обязательная зависимость редактора; его управление действиями не включать в первый этап без задачи. Не использовать этот мод ради отправки простого custom prompt.

Жизненный цикл генерации: draft NPC -> snapshot фактов -> prompt -> queued -> текст/ошибка -> редактирование/сохранение -> экспорт в контекст. Перед спавном можно генерировать на draft JSON без Actor*. В callback проверять save/session token, слот и generation token, чтобы ответ старого запроса не записался новому NPC.

## 9. Предлагаемая архитектура

- SlotRegistry: 160 стабильных записей с NPC base + actor reference, полом и занятостью. Основные состояния Free/Draft/Active/Parked; операции создание/призыв/парковка/освобождение различаются.
- ActorService: имя, раса, голос, характеристики, packages, flags. Работа только на игровом потоке, операции сериализованы на NPC.
- AppearanceService: RaceMenu, проверка совместимости пресета, preview/keep/cancel и восстановление ресурсов.
- PreviewService: независимый lifecycle рендера, view size/visibility и освобождение GPU ресурсов.
- EquipmentService: инвентарь, экипировка, Outfit и biped conflicts; выдача и надевание — разные результаты.
- PresetRepository: JSON с schemaVersion, стабильными plugin+local FormID, зависимости, категории и переносимость между сохранениями.
- SaveState: занятые слоты/состояние конкретного прохождения в SKSE co-save, FormID через ResolveFormID, load/revert callbacks и восстановление изменённых ActorBase.
- SkyrimNetBridge: availability/version gates, custom prompt, собственный bio context; отказ AI не блокирует редактор.
- UiBridge: проверяемые команды/ответы, requestId и revision; frontend не хранит указатели и не делает изменения движка напрямую.

У слота и NPC должны быть разные идентичности. После освобождения/повторного использования слота старые SkyrimNet memories/биография/identity не должны перейти новому персонажу. Это отдельный критерий приёмки, а не только очистка JSON.

Готовые комплекты: сначала vanilla/DLC, варианты стражи по владениям, bandit melee/ranged/mage, бедные/обычные/богатые жители. Форма хранится как plugin+local id; отсутствующий предмет отображается как недоступный. LVLI требует отдельного решения: случайный выбор или зафиксированный результат. Пресет комплекта не должен случайно менять фракции/агрессию и превращать гражданского во врага.

Предлагаемая навигация: NPC / Внешность / Снаряжение / Пресеты / Биография / Настройки. Превью и выбранный NPC сохраняются при переключении вкладок; счётчики занятых слотов отдельно для полов, поиск/фильтры для больших каталогов, неподдерживаемые действия с явной причиной.

## 10. Проверки и открытые решения

| Риск/вопрос | Проверка до обещания функции |
|---|---|
| Постоянный NPC | Создать -> смена ячейки -> fast travel -> ожидание reset -> save/restart/load; та же reference, нет дубликата |
| Откат сохранения | Два сохранения с разными слотами; загрузка старого убирает будущие назначения и настройки базы |
| Внешность | Head/sculpt/tint/hair/eyes, head-only, разные расы/пол; rebuild 3D и reload |
| Cancel | После отмены восстанавливаются лицо/волосы/тело/экипировка, включая ошибку или закрытие окна |
| Превью | Реальный NPC с бронёй и волосами; закрытие/resize/смена актёра; нет утечки device/context state |
| Экипировка | DefaultOutfit не возвращает старую одежду, конфликтующие biped slots учтены, повторное применение не плодит предметы |
| SkyrimNet | Нет мода/старая версия/error/timeout/load while pending/повторный запрос; устаревший ответ отбрасывается |
| Переиспользование слота | Не наследуется чужая AI identity/память и старый FaceGen |
| Совместимость | RaceMenu, NPA, OBody, SMP, custom race, NFF/SeverActions ownership — отдельно, не заявлять заранее |
| Сборка | Корректный ESP, 160+160 форм, все ссылки разрешаются; актуальные PEX если нужны; Magelight assets вместо PrismaUI |

Не решено игровым экспериментом: техника точного actor preview, достаточность RaceMenu native interface для NPA-подобного применения без external exports, точная запись отредактированного текста bio и отслеживание завершения profile update в установленный SkyrimNet и безопасное переиспользование AI identity. Это обязательные исследовательские прототипы следующего этапа.

Рекомендуемый порядок реализации: (1) корректная сборка/ESP + минимальный Magelight; (2) один слот и сохранение; (3) доказательство actor preview и внешности; (4) полный пул 80+80; (5) экипировка/пресеты; (6) SkyrimNet и итоговый интерфейс. Не начинать с красивого UI поверх неработающего движка.
