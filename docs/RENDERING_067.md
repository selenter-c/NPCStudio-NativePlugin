# NPCStudio 0.6.7 — ожидается игровой тест

Исправляется сообщение not-drawing при сохранении в живом редакторе портрета. Реальный NPCStudio.log от 04.11.2026: четыре отказа not-drawing в0.6.6. Ghidra FUN1800391a0 (xref строки180203ac8): framing0 требует уже рисующий Live actor с тем же form, ставит readback текущего кадра в очередь; framing1/2 идут отдельным путём FUN18002d9f0. В0.6.6 ошибочно закрывали Live перед framing0. Теперь editorCapture сохраняет Live, проверяет view/identity/image и использует прямые координаты круга без повторной компенсации zoom/pan. Автоматический маленький портрет framing1 по-прежнему требует закрытия Live. Камера не принимает запоздавшие команды во время readback. Ошибки PNG/файла теперь передаются в UI, у редактора появился тайм-аут6s и повторная попытка после ошибки записи.

Поза: Phantasm.log подтверждает MT_IdleLookingD.hkx поверх Shd_BlockIdle.hkx, который продолжает проигрываться после окончания one-shot. Для превью motion=false с pose=captured сохраняет исходную позу и не проигрывает боевой цикл. Это временно статичная поза, а НЕ решение выбора нейтральной анимации. Поведение NPC в мире не изменяется. Настоящий нейтральный анимированный idle остаётся будущей задачей.

Проверки: incremental build.bat успешен, CTest2/2, Mutagen/ZIP64files; headless Chrome smoke прошёл, включая ошибку записи портрета с сохранением открытого редактора и успешный повтор. Тест UI использует mock provider и не доказывает работу GPU readback в Skyrim. Пользователь должен проверить сохранение/перезапуск и отсутствие перехода в боевую позу. MO2/Skyrim самостоятельно не запускать. Дистрибутив dist/NPCStudio-0.6.7-fomod.zip. Git commit/push ранее разрешены.

Не трогать подтверждённое пользователем восстановление головы/расы. Без миграций старых сохранений. Логотип утверждён. Новые UI масштабы/камера из0.6.6 остаются; native pan на farzoom ограничен провайдером. Следующие крупные задачи: внешность RaceMenu и SkyrimNet биографии.
